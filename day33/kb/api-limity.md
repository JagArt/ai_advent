# API: лимиты и ошибка 429

Лимит на тарифе Pro — 60 запросов в минуту на ключ, на тарифе Team — 600 в минуту на команду, считается скользящим окном. Лимит общий для всех методов.

## Ответ 429 Too Many Requests

При превышении лимита API отвечает `429` с заголовком `Retry-After` — через сколько секунд можно повторить. Правильная реакция клиента — подождать указанное время и повторить запрос, а не слать повторы сразу: каждый отклонённый запрос тоже считается в окне, и клиент, повторяющий без пауз, не выйдет из 429 никогда.

## Как уложиться в лимит

Используйте пакетные методы: `POST /tasks/batch` создаёт до 100 задач одним запросом, `GET /projects/{id}/tasks` отдаёт до 200 задач за раз с пагинацией через `cursor`. Вместо опроса изменений раз в секунду подпишитесь на вебхуки — они не расходуют лимит. Заголовки `X-RateLimit-Remaining` и `X-RateLimit-Reset` в каждом ответе показывают остаток окна.

## Повысить лимит

На тарифе Pro лимит фиксированный. На Team лимит повышается до 3 000 в минуту по запросу через поддержку с описанием сценария; решение принимает команда разработки API в течение 2 рабочих дней.

## Интеграции Планёрки и лимит

Запросы встроенных интеграций — Telegram, Google Calendar, мобильное приложение — в лимит API не входят.
