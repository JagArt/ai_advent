# day4 — температура

Установка, ключи и команда запуска — в [корневом README](../README.md).

Страница состоит из поля ввода, слайдера температуры, кнопки и одного блока ответа. Слайдер идёт от `0` до `2` с шагом `0.1`, рядом числовое поле — они синхронизированы, значение вне диапазона клампится, дробное подгоняется под шаг. Значение по умолчанию — `0.7`. После ответа в шапке блока выводится использованная температура и количество слов.

Сравнение делается вручную: один и тот же промпт отправляется с разными положениями слайдера. Подпись под слайдером меняется по значению:

| Диапазон | Подпись |
| --- | --- |
| 0.0–0.2 | Максимально детерминированно: факты, код, классификация |
| 0.3–0.6 | Баланс точности и разнообразия; хороший default для большинства задач |
| 0.7–1.0 | Более творческие и разнообразные ответы |
| 1.1–1.4 | Высокая вариативность, больше неожиданных формулировок |
| 1.5–2.0 | Очень высокая случайность; выше риск бессвязности и ошибок |

Границы и шаг слайдера (`TEMP_MIN`, `TEMP_MAX`, `TEMP_STEP`), значение по умолчанию (`DEFAULT_TEMPERATURE`) и тексты диапазонов (`TEMPERATURE_BANDS`) заданы в `day4/llm.py` и приходят на страницу через `GET /api/defaults`. Своих значений страница не хранит: до ответа `/api/defaults` слайдер, числовое поле и кнопка выключены — шкала правится в одном месте.

## Выводы по температуре

Замеры на дефолтном промпте: по три генерации на каждое значение, разнообразие — средняя мера Жаккара по множествам слов между парами ответов (чем ниже схожесть, тем сильнее ответы разошлись).

| Настройка | Точность | Креативность | Разнообразие | Для каких задач |
| --- | --- | --- | --- | --- |
| `0` | Максимальная: модель берёт самый вероятный токен, состав и порядок мыслей стабильны | Минимальная: формулировки шаблонные, аналогии предсказуемые | Низкое: схожесть повторных запусков `61%`, отличия в отдельных формулировках | Извлечение фактов, классификация, разбор JSON, генерация и рефакторинг кода, SQL, тесты и всё, что нужно повторить и сравнить |
| `0.7` | Высокая, но факты уже формулируются по-разному | Заметная: появляются живые примеры и небанальные аналогии | Среднее: схожесть `26%`, структура ответа сохраняется | Объяснения, документация, ответы поддержки, черновики текстов — рабочий default для большинства задач |
| `1.2` | Ниже: растёт риск неточностей и вольных утверждений, ответ надо проверять | Высокая: неожиданные метафоры, редкие слова, нестандартные ходы | Большое: схожесть `19%`, каждый запуск — отдельный вариант | Брейншторм, нейминг, слоганы, сюжеты, генерация набора идей, из которых потом выбирают вручную |

Практическое правило: чем важнее правильность и воспроизводимость, тем ниже температура; чем важнее набор непохожих вариантов, тем выше. Выше `1.5` ответы становятся нестабильными — модель начинает терять связность, поэтому такой режим полезен разве что для генерации сырых идей.

Побитовой воспроизводимости при `temperature = 0` нет даже у одного и того же промпта: API не гарантирует детерминизм, поэтому ответы совпадают по смыслу и структуре, но расходятся в отдельных формулировках.

| Файл | Назначение |
| --- | --- |
| `day4/main.py` | FastAPI-приложение, роуты `/`, `GET /api/defaults`, `POST /api/ask` |
| `day4/llm.py` | Клиент DeepSeek, шкала температур, запрос по умолчанию, стрим чанков |
| `day4/static/` | Страница интерфейса: HTML, CSS, JS |

## API

`POST /api/ask` принимает `{"prompt": "...", "temperature": 0.7}` и отдаёт `text/event-stream`: кадры `data: <json-строка>` с частями ответа, затем `event: done` с `{finish_reason, word_count}` либо `event: error` с текстом ошибки. `temperature` вне диапазона `0…2` — ответ `422`.

`GET /api/defaults` возвращает запрос по умолчанию, стартовую температуру, границы слайдера и подписи диапазонов.
