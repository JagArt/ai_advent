# day17 — первый инструмент MCP

Установка, ключи и команда запуска — в [корневом README](../README.md).

День про вызов, а не про рукопожатие: [`day16`](../day16/README.md) уже умеет подключиться и получить список инструментов. Здесь список сам по себе ничего не доказывает — агент должен **вызвать** инструмент, получить результат и ответить по нему. API, вокруг которого собран сервер, — git этого репозитория: модель его историю не знает, поэтому без MCP она откажется, а с MCP прочитает журнал и ответит точно.

## Почему git, а не `add(a, b)`

Инструмент выбран не абстрактный, и это главное решение дня. Сложить два числа модель умеет и без MCP. Сказать, кто сделал последний коммит и какие файлы в нём менялись, — нет. Разница между включённым и выключенным тумблером получается содержательной: инструменты дают не стиль и не рассуждение, а единственное, чего у модели нет, — данные.

Git вызывается списком аргументов, не через shell. Модель передаёт только поля инструмента (`limit`, `ref`), а не произвольную команду, и подставить флаг вроде `-evil` нельзя: такая ревизия отвергается ещё до запуска.

## Инструменты

Описания инструментов SDK берёт из docstring, а описания аргументов — из `Field`, а не из секции `Args`. Схему `inputSchema` собирает сам.

| Инструмент | Аргументы | Что отдаёт |
| --- | --- | --- |
| `git_log` | `limit` 1–30, по умолчанию 10 | последние коммиты: хеш, дата, автор, тема |
| `git_show` | `ref` — хеш, ветка, тег или `HEAD` | сообщение коммита и файлы со статистикой |
| `git_status` | нет | текущая ветка и грязные файлы |

`ref` принимает `HEAD`, `HEAD~2`, короткий хеш и имя ветки. Диапазон `main..HEAD` и строка, начинающаяся с `-`, — `ToolError`: это не ревизия, а способ уехать в произвольные флаги git.

## Клиент вызывает инструмент сам

Задание просит показать возврат результата, и для этого модель не нужна. `python day17/client.py` поднимает сервер, печатает рукопожатие и список, а потом вызывает `git_log(limit=3)`:


Соединение живёт ровно один запрос. Подпроцесс поднимается при входе в `async with`, закрывается при выходе.

## Цикл хода

Как в day16: тумблер MCP, `inputSchema` уезжает в `tools` запроса как есть, модель вызывает, клиент исполняет через `session.call_tool`, результат возвращается сообщением `role="tool"`. Раундов не больше четырёх. Выключенный тумблер сервер не поднимает вовсе.

```mermaid
flowchart TD
    ask["запрос пользователя"] --> onoff{"тумблер MCP"}
    onoff -->|"выключен"| plain["стрим без tools: сервер не поднимается вовсе"]
    onoff -->|"включён"| conn["connect(): подпроцесс, initialize, list_tools"]
    conn --> frame["кадр mcp: сервер, протокол, инструменты, время"]
    frame --> call["стрим с tools"]
    call --> decide{"finish_reason"}
    decide -->|"tool_calls"| run["session.call_tool"]
    run --> toolframe["кадр tool: имя, аргументы, результат, время"]
    toolframe --> call
    decide -->|"stop"| done["кадр done: раундов, вызовов, finish_reason"]
    plain --> done
```

Отказ внутри инструмента — `ToolError`, не `ValueError`: причина доезжает до модели текстом, и у неё остаётся ход на исправление. На вопрос про ревизию `no-such-ref` модель читает `unknown revision` и говорит, что такого коммита нет.

## Прогон: один вопрос с MCP и без

> **Кто сделал последний коммит, когда, и какие файлы в нём менялись?**

*MCP включён — соединение 513 мс, 2 вызова, 2 раунда, `stop`:*

Сначала `git_log(limit=1)`, затем `git_show(ref=HEAD)` — второй вызов зависит от первого: модель узнала хеш и пошла за файлами.

> **Хеш:** `ecf6021`  
> **Автор:** JagArt (соавтор — Cursor)  
> **Дата:** 2026-09-21 16:22:28 +03:00  
> **Тема:** Add day16 with a local MCP server over stdio and a client that lists and calls its tools.
>
> Изменённые файлы (12): `README.md` (+10/−3), `day16/README.md` (+176), `day16/TASK.md`, `day16/agent.py`, `day16/client.py`, `day16/llm.py`, `day16/main.py`, `day16/requirements.txt`, `day16/server.py`, `day16/static/app.js`, `day16/static/index.html`, `day16/static/styles.css`.

*MCP выключен — 0 вызовов, 1 раунд, `stop`:*

> Не знаю: у меня нет доступа к репозиторию AI Advent, поэтому не могу назвать автора, дату и изменённые файлы последнего коммита.

Ответ без MCP — правильный, и это важнее, чем если бы он был выдуманным. Разница между режимами измеряется не «правда против вымысла», а «ответ против отказа»: инструменты дают не стиль, а данные.

Несуществующая ревизия тоже доезжает до модели текстом: `git_show(ref="no-such-ref-xyz")` возвращает `unknown revision`, и у модели остаётся ход сказать, что такого коммита нет, а не молча сочинить.

## Интерфейс

Тумблер `MCP` стоит слева в строке действий. Под формой — панель **Соединение**: рукопожатие и карточки инструментов с аргументами. Панель **Вызовы инструментов** появляется, только если вызовы были: имя с аргументами, время и результат целиком. Под ответом — раунды, число вызовов и `finish_reason`. Кнопка «Проверить соединение» поднимает сервер без модели.

## API

| Метод | Путь | Зачем |
| --- | --- | --- |
| `POST` | `/api/connect` | только соединение и список инструментов, без модели |
| `POST` | `/api/ask` | `{"prompt": "...", "mcp": true}` — ход целиком потоком |

Кадры SSE в `/api/ask`: `mcp` — рукопожатие и инструменты (только при включённом тумблере), безымянные кадры — куски ответа, `tool` — вызов инструмента с аргументами, результатом и временем, `done` — итог хода, `error` — ошибка вместо ответа.
